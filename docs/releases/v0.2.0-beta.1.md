# Hekate v0.2.0-beta.1 — Least-privilege delegation

This release tightens the safety model of cross-harness delegation, makes the
installer non-destructive, and adds a rollback path to the update system. It
contains two breaking changes; read the migration notes below before upgrading.

## Breaking changes

### Delegated harnesses no longer write by default

Every harness in `.workflow/orchestration.yml` now ships twice: an advisory
entry locked to its least-privileged non-interactive mode, and an explicit
writer twin.

| Advisory | Writer twin |
| --- | --- |
| `claude` (`--permission-mode plan`) | `claude-write` (`acceptEdits`) |
| `codex` (`--sandbox read-only`) | `codex-write` (`workspace-write`) |
| `gemini` (default approval mode) | `gemini-write` (`--approval-mode auto_edit`) |
| `opencode` (`--agent plan`) | `opencode-write` (`--agent build`) |
| `aider` (`--chat-mode ask`) | `aider-write` (`--chat-mode code --yes-always`) |

No writer twin uses a bypass-everything mode. `pi` has no permission gate of its
own and is documented as inherently a writer, so it has no twin.

**Migration.** A run that expects file edits must name the writer entry:

```sh
.workflow/bin/hekate-agent run --harness claude-write --task-file task.md
```

Left unchanged, `--harness claude` still succeeds — it returns analysis instead
of edits. Nothing errors, so audit any automation that assumed a diff.

### `install.sh --force` requires consent

`--force` now lists the files it would replace, backs them up under
`.workflow/backups/<UTC-timestamp>/`, and asks for confirmation. Non-interactive
invocations — including `curl … | sh` — abort without writing anything unless
`--yes` / `-Yes` is passed.

**Migration.** Add `--yes` to unattended provisioning that uses `--force`.

## Highlights

- Installable adapters for GitHub Copilot, Gemini CLI, and Aider. `--agents` on
  an update opts an existing installation into a new adapter.
- Per-run timestamped backups bounded to the five most recent runs, recorded in
  `.workflow/state.yml → schema.history`, with
  `update-runner --rollback[=<timestamp>]` to restore one.
- `AGENTS.md` reduced from 338 to 200 lines; the task-history format, delegation
  mechanics, and native-subagent policy moved into lazily loaded
  `.workflow/*.md` documents. No rule was removed.
- The POSIX YAML reader no longer depends on exact 2/4/6-space indentation,
  rejects tab-indented files with a clear error, and distinguishes an absent key
  from an empty one.
- Worker ownership is verified against a recorded process start time instead of
  a substring match on `ps` output.
- Windows `wait` returns the harness exit code, and `logs --follow` streams
  output while the job runs.
- Existing installations receive the changes through migrations 007 and 008.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/MugenKaizen/Hekate/<full-40-character-commit-sha>/install.sh \
  | sh -s -- --commit=<full-40-character-commit-sha>
```

PowerShell 5.1+:

```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
& ([scriptblock]::Create((Invoke-RestMethod https://raw.githubusercontent.com/MugenKaizen/Hekate/<full-40-character-commit-sha>/install.ps1))) -Commit <full-40-character-commit-sha>
```

Pinning the full commit makes the installation inputs immutable.

## Upgrade

```sh
curl -fsSL https://raw.githubusercontent.com/MugenKaizen/Hekate/<full-40-character-commit-sha>/update.sh \
  | sh -s -- --target=. --commit=<full-40-character-commit-sha>
```

The updater applies `007-add-portable-adapters` and `008-add-lazy-load-docs`,
backs the previous tree up under `.workflow/backups/<UTC-timestamp>/`, and
records the run so it can be rolled back:

```sh
./update-runner.sh --target=. --rollback
```

## Beta notes

- The PowerShell half of this release was written and reviewed but never
  executed: no PowerShell interpreter was available during development, so
  `tests/run.ps1` reports `SKIPPED` there. Smoke-test on Windows before relying
  on it.
- Job directories created by v0.1.0-beta.1 are unreadable by these runners; the
  metadata field names were unified across the POSIX and Windows schemes. Drain
  in-flight jobs before upgrading.
- Harness flags and model identifiers remain upstream-version-specific. Run
  `hekate-agent doctor` after upgrading a CLI.

Please report reproducible issues with the harness name/version, command used,
job status, and redacted stderr log.
