# Hekate v0.3.0-beta.1 - Typed policy and enforced Pi sessions

This prerelease introduces a deterministic typed configuration contract,
transactional upgrades from both published portable betas, and an SDK-based Pi
wrapper with mechanical policy enforcement. Read the migration notes before
upgrading a working project.

## Breaking changes

### Fresh projects use the typed v1 contract

Fresh installations author `.workflow/config.yml` and
`.workflow/project.yml`. The compiler derives
`.workflow/status.lock.json`; generated state must not be edited directly.
Legacy `stack.yml`, `architecture.yml`, `conventions.yml`, and `presets.yml`
remain available only through the opt-in `legacy-workflow-files` component.

### Forced portable upgrades are transactional

`install --force` and `update --force` now enter the Node-based transaction
engine. The engine inventories legacy settings, displays an ownership-aware
plan, writes private migration evidence, applies atomically, verifies the
result, and retains exact offline rollback data. Node 20+ is required only for
this forced-upgrade path; the commit-pinned standalone runtime removes the npm
requirement. A fresh static installation still requires neither Node nor npm.

### Runtime enforcement is explicit

`hekate agent` loads Pi through its public SDK and always supplies the Hekate
extension inline. Direct `pi` invocation does not provide wrapper-only
enforcement unless the global extension package is enabled. Pi and the agent
wrapper require Node 22.19+; deterministic core and transactional commands
support Node 20+.

## Highlights

- Strict YAML 1.2 parsing, JSON schemas, deterministic compilation, stable
  diagnostics, and fail-closed readiness states.
- Transactional dry-run, apply, verification, exact-ID rollback, and explicit
  cleanup with interruption-safe recovery.
- Tested import and byte-preserving rollback for `v0.1.0-beta.1` and
  `v0.2.0-beta.1`, including customized, disabled, malformed, CRLF/Unicode, and
  partially migrated installations.
- Ownership-aware manifest installation for Claude, Cursor, Codex, Copilot,
  Gemini, Aider, and Pi adapters.
- Mandatory Pi gate parity across TUI, print, JSON, and RPC modes, including
  live revalidation when a lock becomes stale or forged.
- Optional bounded Pi subagents with advisory isolation, aggregate budgets,
  process-tree cancellation, and worktree-only writers.
- Publishable npm workspaces plus independently locked npm and Bun development
  and package-smoke paths.
- Cross-platform POSIX, PowerShell, wrapper-interoperability, and installed
  tarball coverage.

## Upgrade from a portable beta

Stop active Hekate or delegated-agent processes and make a project backup or
checkpoint first. Use the same trusted full commit SHA for the bootstrap script
and downloaded source.

Inspect the migration without mutation:

```sh
HEKATE_COMMIT='<full-40-character-commit-sha>'
UPDATE_SCRIPT=$(mktemp)
curl -fsSL \
  "https://raw.githubusercontent.com/MugenKaizen/Hekate/$HEKATE_COMMIT/update.sh" \
  -o "$UPDATE_SCRIPT"
sh "$UPDATE_SCRIPT" \
  --target=. \
  --commit="$HEKATE_COMMIT" \
  --force \
  --dry-run
```

Proceed only when unresolved critical settings are zero and every replacement
is expected:

```sh
sh "$UPDATE_SCRIPT" \
  --target=. \
  --commit="$HEKATE_COMMIT" \
  --force \
  --yes
```

Keep the printed transaction ID. Inspect
`.workflow/migration/<transaction-id>/report.json` and the project diff before
continuing normal work.

## Offline rollback

Use the exact transaction ID with the standalone runtime retained inside that
transaction. Do not use the legacy timestamp-based `update.sh --rollback` path
for a v1 transaction.

```sh
node .workflow/transactions/<transaction-id>/runtime/src/hekate-cli.mjs \
  rollback --transaction=<transaction-id> --dry-run --json --target=.
node .workflow/transactions/<transaction-id>/runtime/src/hekate-cli.mjs \
  rollback --transaction=<transaction-id> --yes --json --target=.
```

Rollback evidence is retained indefinitely by default. After the upgraded or
rolled-back project has been accepted, remove only that bundle explicitly:

```sh
node .workflow/transactions/<transaction-id>/runtime/src/hekate-cli.mjs \
  cleanup --transaction=<transaction-id> --dry-run --json --target=.
node .workflow/transactions/<transaction-id>/runtime/src/hekate-cli.mjs \
  cleanup --transaction=<transaction-id> --yes --json --target=.
```

## Install

```sh
HEKATE_COMMIT='<full-40-character-commit-sha>'
curl -fsSL \
  "https://raw.githubusercontent.com/MugenKaizen/Hekate/$HEKATE_COMMIT/install.sh" \
  | sh -s -- --commit="$HEKATE_COMMIT"
```

PowerShell 5.1+:

```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
$HekateCommit = '<full-40-character-commit-sha>'
$Script = Invoke-RestMethod "https://raw.githubusercontent.com/MugenKaizen/Hekate/$HekateCommit/install.ps1"
& ([scriptblock]::Create($Script)) -Commit $HekateCommit
```

## Beta notes

- Provider/OAuth smoke tests require user credentials and are not replaced by
  mocked CI sessions.
- Compatibility with an unpublished next Pi candidate and long-running
  operational soak remain external release evidence.
- A dedicated Hekate TUI is deferred; the wrapper uses the stock Pi TUI without
  forking Pi.
